# TCP注册压测
通过真实 TCP 连接向 `WeLinkServer` 发送注册请求。
每个客户端使用一个持久连接，并在收到上一个请求的响应后再发送下一个请求。
它按项目协议生成 4 字节网络字节序长度头和 JSON 消息体，校验注册响应，并汇总成功率、成功请求吞吐量及成功请求延迟分位数。

压测客户端采用“收到响应后再发下一条”的闭环模式，每个客户端使用一个线程；它适合测注册吞吐基线，不是固定请求速率的压测器。
该版本采用闭环负载：每个客户端等待响应后才发送下一条请求。计时窗口内的第一次请求也会计入结果，所以正式采样前建议先做一次短时运行预热。因此它适合做并发连接下的注册吞吐和延迟基线，不提供固定到达速率，也不模拟成千上万的单线程异步客户端。它不自动清理生成的账号。服务器日志写盘和 MySQL 写入都包含在观测结果中。

压测会向数据库新增用户记录，**请使用专用、可清理的测试数据库，避免对生产库运行**。

输出中的 `successful_requests_per_sec` 是完成成功注册数除以测试实际耗时；p50、p95、p99 和 max 只统计成功请求，延迟从发出请求开始到完整接收并解析响应为止。p50/p95/p99 由固定大小的对数直方图估算，显示对应桶的上界；min/max 是精确值。注册失败会计入失败率并使程序以非零状态退出。

先以低并发做冒烟运行，再逐步提高 `--clients`，对比每档的成功率、吞吐、p95/p99 延迟和服务器/数据库资源。将目标并发和目标延迟阈值按实际部署硬件与产品需求另行确定；本工具不内置 SLA，也不把单次吞吐数字当成容量承诺。

# 运行压测
```shell
./bin/loadTest --host 127.0.0.1 --port 9999 \
  --clients 32 --duration-sec 60 --timeout-ms 5000
```
- clients:客户端数量
- duration-sec:压测持续时间
- timeout-ms:超时时间,一次操作超时则视为失败
